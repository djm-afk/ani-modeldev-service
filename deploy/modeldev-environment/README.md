# One shared ModelDev environment material bundle

These tools prepare the fixed four platform definitions. They do not provision a tenant or switch a Deployment. All Python compilation and tests run on Fedora. Cluster access is exclusively through `ssh kubercloud@100.64.128.12`; deployment changes use the designated delivery service at `http://192.168.25.40:9998/`.

The supported profiles are `modeldev-mlp-cpu`, `modeldev-mlp-gpu`, `modeldev-sft-lora-cpu`, and `modeldev-sft-lora-gpu`. Each IR root has exactly `execution_id`, `spec_hash`, `environment_binding_id`, and `namespace_uid`. No user-supplied IR, Namespace, Pipeline, or Experiment is accepted.

## Prepare and publish

1. Record verified platform inputs, image digests, source commit/tree, explicit compiler inputs for all four profiles, managed registry authority/project, and any exact anonymous-image pull evidence. Never put tokens, DSNs, AK/SK, kubeconfig, or tenant bindings in these files. Unknown live inputs remain blockers.
2. Run `bundle.py compile --config INPUT.json --output PREPARED` with the pinned KFP 2.16.0 Python environment. The output includes the exact raw IR files and SHA256 values. The tool rejects duplicate profiles, bad roots, image drift, and images outside the one managed authority/project without explicit anonymous evidence.
3. Immediately before each write window, run `verify_target.py --output IDENTITY.json`. It checks context, HTTPS API endpoint, configured cluster ID, and kube-system UID against the complete designated-cluster tuple. A receipt older than 60 seconds is rejected for writes.
4. Use `publisher.py --manifest PREPARED/prepared.json --endpoint HTTPS_ENDPOINT --ca-file CA_FILE --token-file PROJECTED_TOKEN_FILE --identity-receipt IDENTITY.json --journal PUBLISH_JOURNAL.json --output PUBLISHED.json`. The publisher creates/reuses only the four exact parent names in `ani-system` and versions named `ir-<first16rawsha>`. It compares full raw digest descriptions and exact GET structure. Before every POST it persists the intent. A lost response permits observation only; an unresolved operation is never resent. Keep the journal for recovery. A foreign same-name parent/version, UID drift, or full-digest mismatch is a conflict.
5. Produce the four canonical Go material files using the published Pipeline/Version IDs and the same raw IR digests, then run `bundle.py seal --published PUBLISHED.json --materials MATERIAL_DIRECTORY --output SEALED`. The result has exactly four canonical materials, four original IRs, and canonical `manifest.json`. The manifest raw SHA256 is the bundle identity.

KFP v2 `GetPipelineVersion.pipeline_spec` is a protobuf Struct; it cannot preserve YAML bytes. The pinned official server helper `api_util.go` converts two documents to `{pipeline_spec: doc1, platform_spec: doc2}` (one document stays unchanged). Accordingly, the raw immutable IR file is hashed against the frozen SHA and the complete server Struct is compared to that official projection. The raw hash is never redefined as a re-serialized JSON hash. Primary sources: [pipeline.proto](https://github.com/kubeflow/pipelines/blob/85a38e0719870e5b2f97a74f5c966d79bcc7c960/backend/api/v2beta1/pipeline.proto#L185), [api_util.go](https://github.com/kubeflow/pipelines/blob/85a38e0719870e5b2f97a74f5c966d79bcc7c960/backend/src/apiserver/server/api_util.go#L152).

## Render the switch inputs

Run `platform_config.py --template VERIFIED_PLATFORM.json --bundle SEALED --output PLATFORM.json`; bundle-derived profile fields cannot be overridden. Validate the final file with the production Go loader. Run `render.py --bundle SEALED --platform PLATFORM.json --service-image SERVICE_DIGEST --copy-image WEBHOOK_DIGEST --artifact-source-secret OBSERVED_SECRET --service-container modeldev --webhook-container webhook --output RENDERED`. Deployment names default to the observed `ani-modeldev` and `ani-modeldev-webhook`; confirm current names and container names before applying.

The material-copy image must equal the bundle-pinned webhook image and provide `/usr/local/bin/ani-modeldev-webhook --copy-materials-from /source --copy-materials-to /materials --copy-materials-manifest-sha256 SHA`. It verifies all eight file hashes and copies to regular files in an EmptyDir. Both runtime containers mount the identical directory read-only. A second service-only init uses the same pinned webhook image with `--copy-platform-from /source/platform.json --copy-platform-to /platform/platform.json --copy-platform-sha256 SHA`; this independently pinned configuration is copied from its ConfigMap into a separate regular-file EmptyDir because the production platform loader also uses O_NOFOLLOW. The platform file is not added to the material manifest, avoiding a digest self-reference. The source ConfigMap is immutable; no subPath mount pins token rotation. KFP and Kubernetes control tokens have separate projected audiences and file paths. Artifact credentials are a referenced two-key Secret (`access_key`, `secret_key`) mounted as files; they are independent of workload STS.

The policy owner renderers `deploy/modeldev-tenant-policy/render.py` and `deploy/modeldev-webhook/render.py` supply exact native policies/bootstrap and webhook configuration. Native configuration contains the observed exact control/webhook/KFP/Argo/Trainer/JobSet/Job/persistence/maintenance principals, exact node principals, and the actual KFP CA key. Install and verify native policy before granting create/bind. The service configuration has no per-tenant list.
