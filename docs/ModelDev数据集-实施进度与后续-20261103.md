## 三、必须知道的偏差与遗留问题

### 3.1 设计文档里的 NUL 分隔在 PostgreSQL 不可实现

设计附录 A.7 定义目标提交锁键为 `SHA256("ani.modeldev.dataset-target-commit.v1" + NUL + tenant_uuid + NUL + cluster_uuid)`。

**实际情况**：PostgreSQL 的 `text` 类型不允许 NUL，`chr(0)` 直接报 `null character not permitted`。

**处理**：改用 `bytea` 拼接（`convert_to(prefix,'UTF8') || decode('00','hex') || ...`），哈希的**字节串与设计完全一致**，只是绕过了 text 类型的限制。实测键值 `3561915907020135758`，与 Go 侧 `DatasetTargetCommitLockKey` 逐位相同，并有固定向量测试守护。

**处置结论（2026-11-04 确认）**：设计附录 A.7 的 `NUL` 是**字节串语义**，不是要求 PostgreSQL 的 `text` 字面量含 NUL。实现按字节串实现即满足合同，无需改设计文档；此处记录实现方式，供后续复核者不必重查。

### 3.1b 分支已推送，Gov pin 只能用 `replace`

**事实**：`feat/modeldev-dataset` 已推送到 `fork/djm-afk`，HEAD 为 `2571d89b2dc42b1bb81ba3e402ae7141495678a6`。

**但 fork 的模块路径与上游不同**：

因此 `go get github.com/djm-afk/ani-modeldev-service@feat/modeldev-dataset` 会报
`module declares its path as: github.com/zhangzhe-ctrl/ani-modeldev-service but was required as: github.com/djm-afk/ani-modeldev-service`。

### 3.7 Gov `make api` 生成链在当前基线上跑不通（C4-2 的实际阻塞）

**这不是本次改动引入的问题。** 任何人在 `origin/main` 上执行 `make api` 都会遇到同样的失败。

**冲突事实**：

| 来源 | `protoc-gen-go-grpc` | `protoc-gen-go-http` |
| --- | --- | --- |
| `tools/config/tool-lock.json` | `v1.6.2` | `v2.0.0-20260404020628-f149714c1d54` |
| `api/buf.accelerator.gen.yaml`、`buf.aksk`、`buf.network`、`buf.quota`、`buf.quota-release` | `v1.6.0` | `v2.0.0-20251205160234-b9fab9a5a5ab` |

`gow api` 的 preflight 要求两者一致，因此必然失败，报 `tools/config/tool-lock.json pins ...`。

**另外两个环境问题**（在 192.168.18.35 与 WSL 上分别遇到）：

1. 35 上全量 `buf generate` 时插件被 `signal: killed`（内存不足）。buf 在写入前已清空输出目录，**421 个生成文件被删**；已 `git checkout -- .` 完全恢复。
2. WSL 内 `scripts/build-redact-plugin.sh` 报 `error obtaining VCS status: exit status 128`，因为 worktree 的 `.git` 指针是 Windows 路径形式。为构建临时改过指针，**已恢复为原值**。

**给后续会话的处理建议**：

- 先用一台 git 干净（非 Windows worktree 指针）、内存 ≥ 8 GiB 的 Linux 主机；
- 二选一：把 5 个旧 yaml 的插件版本统一到 `tool-lock.json`（这是一次独立的重构，需要单独授权），或按 `tool-lock.json` 安装插件并只生成 ModelDev 相关路径；

- 生成后用 `git status --porcelain api/gen | wc -l` 确认影响面只含 modeldev/admin 的相关文件。
